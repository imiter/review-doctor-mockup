# 리뷰 관리 답글 카드 재설계 — "직접 쓰기" / "AI 추천 답글 보기" 분리 + Mock 문구 정리

## 배경

`2026-08-21-llm-rag-reply-design.md`(코어 설계)로 불만 카테고리 리뷰는 이미
실제 Claude API 기반 RAG 답글 생성이 배포됐다. 그런데 `frontend/src/app/
(app)/reviews/page.tsx`의 UI 문구는 그 이전(전부 템플릿 Mock이던 시절) 그대로
남아있다 — "답글 생성 (Mock)" 버튼, "답글 생성은 스타일 템플릿 기반 Mock —
실제 AI 호출 없음" 안내문. 사용자가 실제 배포 사이트를 확인하다가 이 문구를
보고 "아직도 Mock이냐"고 오해했다.

조사 중 문구 문제와 별개로 실제 UX 모순도 하나 확인했다: 지금 화면은 답글
스타일(발랄 이모지 파티/진중맨/무난 요정/진지한 하이개그) 드롭다운을 리뷰
종류와 무관하게 항상 보여주지만, 백엔드(`backend/app/routers/reviews.py`의
`generate_reply`)는 `category == "no_issue"`(칭찬/무난 리뷰)일 때만 그 스타일을
실제로 쓰고, 불만 카테고리 리뷰는 `generate_ai_reply`(RAG)가 스타일 선택을
완전히 무시한 채 항상 사장님의 학습된 말투로만 생성한다. 즉 불만 리뷰에서는
어떤 페르소나를 골라도 결과가 똑같다 — 사용자가 눈치채지 못한 기존 버그다.

사용자가 참고로 리뷰닥터/세일즈랩류 경쟁사 화면 스크린샷 2장을 첨부하며 비슷한
느낌으로 만들어달라고 요청했다. 이 프로젝트 CLAUDE.md는 "리뷰닥터/세일즈랩을
벤치마크했지만 화면을 복제한 것이 아니라 분석 후 재설계했다"를 명시적 원칙으로
두고 있어 그대로 복제는 금지다. 사용자에게 이 충돌을 먼저 짚었고, 스샷에서
구조적 아이디어(답글 작성 버튼을 "직접 쓰기"/"AI 추천 보기" 둘로 분리)만
가져오고 시각 디자인은 이 프로젝트의 다크 테마로 독자적으로 재설계하기로
합의했다.

이 문서가 다루는 건 브레인스토밍에서 사용자와 함께 4개 작업으로 분해한 것 중
**1번(문구 정리 + 리뷰 카드 UI 재설계)**다. 나머지 3개(페르소나+RAG 통합,
배민 리뷰 이미지 첨부, 별점-내용 불일치 시 이모지 제거)는 각각 별도 스펙로
분리한다 — 특히 페르소나+RAG 통합은 지금 "무난한 리뷰는 무료 템플릿, 불만
리뷰만 유료 API"로 비용을 통제해온 기존 설계 결정을 뒤집는 변화라 별도의
비용/설계 논의가 필요하고, 이미지 첨부는 배민 리뷰 API 응답에 이미지 필드가
실제로 오는지 아직 코드로 확인되지 않아 실 계정 검증이 먼저 필요하다.

## 목표 / 비목표

**목표**
- 답글 작성 진입점을 "직접 쓰기"(AI 호출 없음)와 "AI 추천 답글 보기"(기존
  `/generate-reply` 재사용) 두 버튼으로 명시적으로 분리한다.
- "Mock"이라는 표현과 "실제 AI 호출 없음" 안내문을 실제 동작(칭찬 리뷰는
  템플릿, 불만 리뷰는 실제 RAG)을 정확히 설명하는 문구로 바꾼다.
- AI 추천 답글에 "다시 생성" 버튼을 추가해 마음에 안 들면 재생성할 수 있게
  한다(같은 `/generate-reply` 재호출, 새 백엔드 로직 없음).

**비목표**
- 백엔드 변경 없음 — `/generate-reply`, `/reply` 등 기존 API는 그대로 재사용.
  이 스펙은 순수 프론트엔드 UI/UX 재설계다.
- 페르소나 스타일이 불만 리뷰의 RAG 생성 결과에 실제로 영향을 주게 만드는
  것(그 버그 자체를 고치는 것)은 이번 범위가 아니다 — 다음 스펙(페르소나+RAG
  통합)에서 다룬다. 이번 스펙은 그 제약이 있는 채로 UI만 재설계한다(스타일
  드롭다운은 "AI 추천 답글 보기" 패널 안에 그대로 두되, 그 문구가 불만
  리뷰에서는 결과에 영향을 안 준다는 걸 새로 숨기거나 왜곡하지 않는다 —
  다음 스펙에서 실제로 반영되기 전까지는 정직하게 동작한다).
- 경쟁사 스크린샷의 시각 디자인(색상, 아이콘, "Pro" 배지, 요금제 업셀 문구
  등)을 그대로 가져오지 않는다 — 이 프로젝트의 다크 테마·기존 컴포넌트
  스타일(`Card`, `rounded-lg`, `text-accent` 등)로 재해석한다.
- 리뷰 이미지 첨부는 다루지 않는다(별도 스펙).

## 아키텍처

`ReviewCard` 컴포넌트(`frontend/src/app/(app)/reviews/page.tsx`)의 답글 없는
리뷰 렌더링 분기를 상태 기계로 재구성한다:

```
[답글 없음]
   │
   ├─ "직접 답글 쓰기" 클릭 → [수동 작성 모드]
   │                              (빈 텍스트 영역, AI 호출 없음)
   │
   └─ "AI 추천 답글 보기" 클릭 → [AI 추천 모드]
                                    │  (스타일 드롭다운 + "다시 생성" 버튼 +
                                    │   /generate-reply 결과)
                                    │
                        둘 다 → [편집 가능한 텍스트 영역]
                                    │  (기존 "미리보기 — 등록 전 자유롭게
                                    │   수정하세요" 블록 재사용)
                                    ▼
                            "이대로 답글 등록" → POST /reviews/{id}/reply
```

`draft`(텍스트 내용)와 `mode`("idle" | "manual" | "ai") 두 상태로 표현한다.
`mode`가 `"idle"`이면 버튼 2개만 보이고, `"manual"`이면 빈 텍스트 영역이
바로 열리고(스타일 드롭다운 없음), `"ai"`이면 스타일 드롭다운 + "다시 생성" +
AI가 채운 텍스트 영역이 보인다. 두 모드 모두 텍스트 영역 자체는 자유 편집
가능하고, "이대로 답글 등록"을 누르면 현재 `draft` 값을 그대로 저장한다 —
수동으로 썼든 AI 초안을 고쳤든 저장 로직은 동일하다(기존 `save()` 그대로
재사용).

`generate()`(기존 함수, `/generate-reply` 호출)는 그대로 두고 "AI 추천 답글
보기" 버튼과 "다시 생성" 버튼 둘 다 이 함수를 호출한다. 새 상태 `mode`는
버튼 클릭 시 로컬로만 설정하고 서버에 저장하지 않는다(리뷰 목록을
새로고침해도 어차피 초기화되는 게 맞다 — 아직 저장 전 임시 UI 상태).

## 화면 문구

- 페이지 상단 안내문: "답글 생성은 스타일 템플릿 기반 Mock — 실제 AI 호출
  없음" → "칭찬 리뷰는 스타일 템플릿으로, 불만 리뷰는 실제 AI가 사장님
  말투를 학습해 답글을 생성해요"
- "직접 답글 쓰기" 버튼: 테두리만 있는 무채색 버튼(`border-border-subtle`,
  `text-muted`), 아이콘 없음
- "AI 추천 답글 보기" 버튼: 강조색 버튼(`bg-accent`), ✨ 또는 유사한 아이콘
- "다시 생성" 버튼: AI 추천 패널 안, 작은 아이콘 버튼(회전 화살표 아이콘),
  `generate()` 재호출 중에는 `disabled`. 클릭하면 현재 텍스트 영역에 편집
  중이던 내용(있다면)을 그대로 덮어쓴다 — 되돌릴 방법은 따로 없으니, 이미
  많이 고친 상태에서 실수로 누르는 걸 막기 위해 텍스트 영역 내용이
  `draft_reply`로 받은 원본과 달라져 있으면(직접 수정한 흔적이 있으면)
  `window.confirm`으로 한 번 확인한다.
- AI 추천 패널 헤더: "AI 추천 답글" (참고 스샷의 "Pro" 배지·요금제 업셀
  문구는 넣지 않는다 — 이 프로젝트는 이미 별도 Basic/Pro 답글 생성 한도
  체계가 있고, 그 로직은 `generate()`의 기존 `reply_limit_exceeded` 에러
  처리로 이미 커버된다)

## 에러 처리

기존 `generateError` 상태(한도 초과 등)를 그대로 재사용한다. "AI 추천 답글
보기"/"다시 생성" 클릭 시 에러가 나면 AI 추천 패널 자리에 에러 메시지를
보여주고 "수동 작성 모드"로의 전환 버튼을 함께 제공한다(한도를 다 써서 AI를
못 쓰더라도 사장님이 직접 쓰는 경로는 항상 열려있어야 한다).

## 테스트 계획

이 프로젝트 프론트엔드는 자동화 테스트가 없다(`npm test` 스크립트 없음,
기존 온보딩 기능 때와 동일한 제약). 검증은 `npm run build`(타입 체크)와
`npm run lint`, 그리고 dev 서버에서 다음을 직접 확인한다:
- 답글 없는 리뷰에 버튼 2개가 나오는지
- "직접 답글 쓰기" → AI 호출 없이 빈 텍스트 영역이 바로 열리는지(네트워크
  탭에서 `/generate-reply` 호출이 없는지 확인)
- "AI 추천 답글 보기" → 실제 답글이 채워지는지(칭찬 리뷰 vs 불만 리뷰 둘 다)
- "다시 생성" → 다시 호출되고 내용이 바뀌는지(또는 같은 골든 예시 기반이라
  비슷하게 나올 수 있음 — 호출 자체가 되는지가 핵심)
- 두 경로 모두 텍스트 영역 편집 후 "이대로 답글 등록"으로 정상 저장되는지
- 한도 초과 시 에러 메시지 + 수동 작성 전환이 되는지
