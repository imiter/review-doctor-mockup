# 모바일 대시보드/리뷰/광고 UI·UX 리팩토링

## 배경

Toss 결제 연동을 마치고 실제 데모 계정(`demo@dris.kr`, 치밥대장)으로 모바일
앱 전 화면을 실데이터로 검증하는 과정에서, 기능은 웹과 동등하게 다 붙었지만
"정리가 안 되고 어디에 뭐가 있는지 모르겠다"는 피드백을 받았다(2026-08-30).
구체적으로 4가지가 지적됐다:

1. 대시보드가 숫자 카드로만 빽빽해서 가독성이 떨어진다 — 원형 그래프 같은
   시각적 요소가 필요하다.
2. 우가클 점수 카드의 브랜드 선택이 라벨 옆에 pill을 나열하는 방식이라
   지저분하다 — 드롭다운이어야 한다.
3. 리뷰 관리 화면의 "규칙"/"스타일" 링크가 우측 상단에 작은 텍스트로만
   있어서 처음 쓰는 사람은 있는지도 모른다.
4. 광고 순위 모니터링의 캠페인이 "치킨"/"찜·탕·찌개"처럼 카테고리로만
   표시돼서, 여러 브랜드를 가진 계정은 이게 내 어느 매장인지 알 수 없다.

## 시각적 방향

토스(Toss)의 카드/도넛 게이지 언어를 기본 틀로 삼는다 — 점수형 지표(0~100)는
링 게이지로, 카드 테두리는 얇게, 여백을 넉넉히 둔다. 정보 위계는 Linear
스타일(타이포그래피 크기·명도차로 1급/2급 지표를 구분)을 참고한다. 팔레트는
바꾸지 않는다(`src/theme/colors.ts` 그대로 — 보라 accent `#6D5EF5`, 배경
`#0B0E14`).

## 범위: 이번 스코프는 모바일 앱 우선

지적된 4가지 모두 웹에도 존재하지만(4번은 특히 웹도 카테고리만 표시), 이번
패스는 **모바일 앱**을 먼저 고치고 웹은 이어서 같은 방향으로 적용한다(4번의
백엔드 변경은 웹·앱이 공유하므로 이번에 같이 끝난다). 이렇게 나누는 이유:
지금 활성 작업 표면이 앱이고, 웹의 우가클 선택은 이미 네이티브 `<select>`라
드롭다운 자체는 있다(pill 나열 문제는 앱에만 있음) — 웹 쪽은 스타일 다듬기
정도로 범위가 작다.

## 1. 링 게이지 / 임계값 바 컴포넌트 (신규)

`react-native-svg`를 새로 설치한다(순수 SVG `<Circle>`의
`strokeDasharray`/`strokeDashoffset`로 원형 게이지를 그리는 표준 기법이라
차트 라이브러리 전체를 끌어올 필요가 없다). 새 컴포넌트 2개:

- `RingGauge` (`src/components/RingGauge.tsx`): `value`(0~100), `size`,
  `label`, `color` props. 0~100 점수형 지표 전용 — 우가클 점수, 광고 성과
  점수, 재주문율(%)에 쓴다. 색상은 acos.py의 점수 구간(90+/80+/70+/미만)과
  동일한 임계값을 그대로 재사용해 초록/보라(accent)/주황/빨강 4단계로
  나눈다.
- `ThresholdBar` (`src/components/ThresholdBar.tsx`): ACoS처럼 "낮을수록
  좋음"인 지표용 가로 막대. 배경에 안전/주의/위험 3구간을 얇은 색 밴드로
  깔고 그 위에 현재값 위치를 점으로 찍는다. acos.py의 10%/15%/25% 경계값을
  그대로 가져온다(경계값이 바뀌면 두 군데를 따로 고쳐야 하는 걸 피하려면
  원래는 백엔드가 구간까지 계산해서 내려주는 게 이상적이지만, 이번 스코프는
  UI 리팩토링이라 프론트 상수로 하드코딩하고 acos.py 주석에 "UI 쪽에도 같은
  값이 있다"고 남긴다).

적용 위치:
- 대시보드 "우가클 점수" 카드: 점수 → RingGauge, ACoS → ThresholdBar.
- 대시보드 "재주문율(보정)" 카드: RingGauge.
- 광고 탭 "광고 성과" 그리드의 각 카드: 성과 점수 → RingGauge, ACoS →
  ThresholdBar.
- 매출 분석 모달, 일별 매출/입금 막대 그래프(이미 막대 형태로 있음)는 이번
  스코프에서 안 건드린다 — 이미 시각화가 돼 있는 지표라 우선순위 밖.

## 2. 우가클 브랜드 선택 → 드롭다운

지금 대시보드 카드 헤더에 가로로 나열되는 브랜드 pill 목록을 없애고, 카드
헤더에 현재 선택된 브랜드명 + 셰브론(`›`)만 남긴 pressable 한 줄로
바꾼다. 탭하면 이미 있는 `DetailModal` 패턴을 재사용한 바텀시트가 열리고
브랜드 목록이 세로로 나열된다(선택 즉시 시트 닫힘). 새 컴포넌트 없이
`DetailModal` + 리스트로 충분하다.

## 3. 리뷰 관리 — 규칙/스타일 카드화

`ReviewsScreen.tsx` 상단의 작은 텍스트 링크 2개를 없애고, 리뷰 목록 위에
"답글 설정" 섹션을 새로 추가한다: 아이콘 + "답글 규칙"/"답글 스타일" 제목 +
한 줄 설명(예: "자동 제출 조건과 별점 규칙" / "말투와 페르소나") 을 가진
가로 2분할 카드 2개. `ListRow`의 `icon` prop을 재사용해 일관된 스타일을
유지한다.

## 4. 광고 캠페인 — 브랜드명 표시 (백엔드 + 웹 + 앱)

**백엔드** (`backend/app/routers/ads.py`): `shop_no`가 있는 캠페인만 실제
브랜드명을 붙인다. `backend/app/llm/generate.py`의 `_resolve_display_name`과
동일한 조회·정제 로직(`BaeminShopBrand` → `[...]` 태그 제거 → `" / "` 앞부분만)을
쓰는 작은 헬퍼를 `ads.py`에 추가하고, `/ads/rank-monitoring`과
`/ads/performance` 응답에 `display_name: str | None` 필드를 추가한다
(`shop_no`가 없으면 `null` — Mock 카테고리 캠페인은 애초에 특정 매장이
아니므로 브랜드명 자체가 없다). 기존 `category` 필드는 그대로 유지한다
(UI에서 "치밥대장 당고점 · 치킨"처럼 같이 보여줄 것이므로).

**모바일** (`AdsScreen.tsx`): 카드 제목을
`item.display_name ? `${item.display_name} · ${item.category}` : item.category`로.

**웹**: 같은 패턴을 `frontend/src/app/(app)/ads/page.tsx`의 테이블 카테고리
셀에 적용.

## 영향받지 않는 것

- API 계약의 기존 필드는 전부 유지(추가만 함) — `display_name`은 optional
  이라 다른 소비자에 영향 없음.
- 인증/네비게이션/결제 플로우는 이번 스코프 밖.
- 대시보드의 매출/입금 카드, 주문내역, 계정 화면은 이미 검증된 그대로 둔다.

## 테스트 방법

`react-native-svg` 설치 후 네이티브 리빌드가 필요하다(WebView 추가 때와
동일한 패턴). 실기기 대신 시뮬레이터 + idb로 각 화면을 스크린샷 검증한다.
`demo@dris.kr` 실데이터로 우가클/재주문율/광고 성과 링 게이지가 올바른
색상 구간에 들어가는지, 브랜드 드롭다운이 실제 4개 브랜드를 보여주는지,
"치킨" 캠페인만 브랜드명이 붙고 나머지 3개는 카테고리만 남는지 확인한다.
