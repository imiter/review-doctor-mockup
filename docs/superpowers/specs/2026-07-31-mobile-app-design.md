# React Native 모바일 앱 (iOS) — 설계서

- 날짜: 2026-07-31
- 작성 배경: 웹(FastAPI + Next.js)이 이미 완성·배포된 상태에서, 같은 백엔드를
  쓰는 iOS 앱을 추가로 만들어달라는 요청. macOS + Xcode 환경.
- `CLAUDE.md`는 원래 "Flutter 앱 구현 금지"로 모바일 앱 자체를 범위 밖에 뒀으나,
  이번 결정으로 예외를 허용했다(`CLAUDE.md`의 "모바일 앱 (예외 허용)" 절 참고).
  새 백엔드 엔드포인트를 만들지 않고 기존 FastAPI Mock API를 그대로 재사용한다는
  점에서, "새로운 실제 연동 추가"가 아니라 "이미 있는 Mock 데이터를 다른
  클라이언트로도 보여준다"는 성격의 확장이다.

## 목적

웹과 같은 다크 테마 분위기로, 배달매장 사장이 자주 확인할 핵심 화면 4개를
iOS 앱에서도 볼 수 있게 한다.

## 범위와 원칙

- **화면 4개만**: 대시보드, 리뷰 관리, 광고 순위 모니터링, 매출. 웹의 나머지
  5개 화면(답글 스타일 설정, 답글 규칙 설정, 2차 답글 등록, 주문내역, 가게
  연결, 계정 관리)은 이번 범위 밖 — 전부 설정성 화면이라 앱에서의 가치가
  상대적으로 낮다고 판단했다.
- **"우리가게 순위 확인" 버튼은 앱에 넣지 않는다.** 이 기능은 개발자의 맥북
  로컬 에뮬레이터(Appium)를 조작하는 기능이라 폰에서 누르는 게 의미가 없다.
  광고 순위 모니터링 화면은 조회 전용으로만 만든다.
- **매장 전환 UI를 만들지 않는다.** 백엔드가 `store_id`를 안 주면 사장님의
  첫 매장으로 기본 처리하는 로직을 이미 갖고 있어서, 화면 4개짜리 앱에는
  안 맞는 복잡도로 보고 뺐다.
- **iOS 시뮬레이터 대상**. Android는 이번 범위 밖 (React Native 자체는
  크로스플랫폼이라 나중에 큰 재작업 없이 확장 가능하지만, 지금은 만들지도
  검증하지도 않는다).
- 복잡한 권한/다중 사업자 권한 관리는 여전히 금지 — 웹과 동일하게 사장 1명 =
  로그인 1개 기준.
- 새 백엔드 엔드포인트는 만들지 않는다. 기존 웹이 쓰는 API를 그대로 재사용한다.

## 접근 방식

**Expo (managed workflow)**를 쓴다. `npx create-expo-app`으로 시작해서
`npx expo run:ios`로 Xcode/iOS 시뮬레이터에서 빌드·실행한다. 이 앱은 카메라·
블루투스 같은 네이티브 모듈이 전혀 필요 없는 "REST API 붙여서 화면 보여주기"
앱이라, bare React Native CLI(네이티브 프로젝트 직접 관리)의 자유도가 필요
없다. Expo가 폰트·아이콘·상태바 설정을 config 한 줄로 처리해줘서 이 프로젝트
성격(교육 과제물, 범위 통제)에 더 맞는다.

## 아키텍처 (파일 구조)

메인 프로젝트와 형제 위치인 저장소 루트의 `mobile/` 폴더:

```
mobile/
├── app.json                  # Expo 설정 (다크 테마 기본, 앱 이름/아이콘)
├── App.tsx                   # 진입점 — 인증 상태에 따라 로그인 스택 / 탭 네비게이터 분기
├── src/
│   ├── theme.ts              # 웹 globals.css의 색상 토큰을 그대로 옮긴 상수
│   ├── lib/
│   │   ├── api.ts            # 웹 frontend/src/lib/api.ts 이식 (apiGet/apiPost, 토큰 보관)
│   │   └── auth.ts           # expo-secure-store 기반 토큰 저장/조회/삭제
│   ├── components/
│   │   ├── Card.tsx           # 웹 Card.tsx와 동일한 룩(rounded, border, surface bg)
│   │   └── StatTile.tsx       # 대시보드 숫자 카드 (매출/재주문율 등 반복 사용)
│   ├── navigation/
│   │   └── RootNavigator.tsx  # 로그인 스택 + 하단 탭 네비게이터(4개 화면) 구성
│   └── screens/
│       ├── LoginScreen.tsx
│       ├── DashboardScreen.tsx
│       ├── ReviewsScreen.tsx       # 목록 + 상세(답글 생성) 겸용
│       ├── AdsScreen.tsx           # 순위 현황(Mock) + 반경별 실측 순위(조회 전용)
│       └── SalesScreen.tsx
└── package.json
```

`theme.ts`, `lib/api.ts`는 웹의 대응 파일과 값·구조를 최대한 1:1로 맞춰서,
두 코드베이스를 나란히 봤을 때 대응 관계가 바로 보이게 한다.

## 화면 구성

1. **로그인** — 이메일/비밀번호 입력 + "데모 계정으로 로그인" 버튼(웹과 동일
   데모 계정 `demo@dris.kr`). 로그인 성공 시 토큰을 `expo-secure-store`에
   저장하고 탭 네비게이터로 전환.
2. **대시보드** — 기간 토글(오늘·1주·1개월·이번달) + 매출/입금 카드, 답글
   대기 리뷰 수, 재주문율, ACoS 요약, 안읽은 알림 목록. 웹의 카드 그리드를
   세로 스크롤 목록으로 재배치.
3. **리뷰 관리** — 상태 필터 칩(대기/검토중/완료) + 리뷰 목록. 리뷰를 탭하면
   상세로 이동해 답글 스타일 선택 → Mock 답글 생성 → 수정 → 등록까지 웹과
   동일한 플로우.
4. **광고 순위 모니터링** — 순위 현황(Mock 시간대별 스냅샷) 표 + 반경별 실측
   순위(0km/1.5~2.5km/2.5~3.5km) 표. 둘 다 조회 전용, 실행 버튼 없음.
5. **매출** — 기간 토글 + 매출/입금 막대 그래프(간단한 바 형태, 차트 라이브러리
   없이 View 너비로 표현 — 웹의 sales 페이지 막대와 동일한 방식), 플랫폼별 내역.

## 데이터 흐름

- API 베이스 URL 기본값은 `http://localhost:8000` — iOS 시뮬레이터는 맥의
  `localhost`를 그대로 공유해서 별도 프록시/IP 설정이 필요 없다.
- 인증: 로그인 시 받은 JWT를 `expo-secure-store`에 저장하고, 이후 모든 요청에
  `Authorization: Bearer <token>` 헤더로 첨부. 웹의 `apiGet`/`apiPost` 패턴을
  그대로 이식한다.
- `store_id`는 요청에 아예 넣지 않는다 — 백엔드가 사장님의 첫 매장으로 기본
  처리한다 (위 "범위와 원칙" 참고).
- 각 화면은 웹처럼 화면 진입 시 `useEffect` + `apiGet`으로 데이터를 가져오는
  단순한 방식을 쓴다. React Query 등 데이터 페칭 라이브러리는 이 규모(화면
  4개, 클라이언트 캐싱 요구 없음)에는 과하다고 보고 안 쓴다(YAGNI).

## 에러 처리

- 401 응답 → 저장된 토큰 삭제 후 로그인 화면으로 전환. 웹의 `ApiError` 처리와
  동일한 원칙.
- 그 외 API 에러 → 화면 안에 인라인 에러 배너 한 줄로 표시. 자동 재시도 로직은
  만들지 않는다.

## 디자인 시스템

- `theme.ts`에 웹 `globals.css`의 값을 그대로 옮긴다: 배경 `#0b0e14`, 카드
  `#12161f`, 카드2 `#171c27`, 테두리 `#232935`, 본문 텍스트 `#e7e9ee`, 보조
  텍스트 `#8b93a7`, 포인트(보라) `#6d5ef5`, 성공(초록) `#34d399`, 경고(노랑)
  `#fbbf24`, 위험(빨강) `#f87171`.
- 폰트는 웹의 Geist를 앱에 강제로 번들링하지 않고 **iOS 시스템 폰트(San
  Francisco)를 그대로 쓴다** — 폰트 로딩 복잡도 없이도 "다크테마 + 깔끔한
  산세리프"라는 같은 인상은 유지되고, iOS 네이티브 느낌도 살아난다.
- `Card` 컴포넌트는 웹의 `rounded-2xl border border-border-subtle bg-surface
  p-5` 룩을 RN `StyleSheet`로 매핑(모서리 radius 16, 테두리 1px, 패딩 20).
- 하단 탭바는 surface 배경 + 선택된 탭만 포인트 보라색.
- 아이콘은 `@expo/vector-icons`(Ionicons)로 웹 사이드바 아이콘과 비슷한
  라인 스타일을 고른다.

## 테스트

- `tsc --noEmit` 타입체크를 기본 검증으로 쓴다 (웹 frontend와 동일 기준).
- Jest 컴포넌트 테스트·E2E(Detox 등)는 이 프로젝트 성격(교육 과제물, 범위
  통제)에 비해 과하다고 보고 만들지 않는다.
- 최종 검증은 iOS 시뮬레이터를 직접 실행해 로그인 → 4개 화면을 순서대로
  띄워보고 스크린샷으로 확인하는 수동 확인으로 대신한다.

## 산출물 (이번 스펙의 완료 기준)

- `mobile/`에 Expo 프로젝트가 생성되고, `npx expo run:ios`로 시뮬레이터에서
  실행된다.
- 데모 계정으로 로그인 → 하단 탭 4개(대시보드/리뷰관리/광고순위모니터링/매출)
  전부 실제 백엔드 데이터를 받아와 웹과 같은 다크 테마로 렌더링된다.
- `tsc --noEmit` 통과.
